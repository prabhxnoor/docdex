# docdex v0.5.0 — Conflict v2 (M1 / Phase 4, piece 5 of 5*)

> *Built before piece 4 (embeddings/RRF) at the user's request. Per-release
> design doc; living plan is [`ROADMAP.md`](../ROADMAP.md).

_Date: 2026-07-22 · Branch: `feat/v0.5.0-conflict-v2`_

---

## 1. Goal

Make the `## Conflicts` section **more trustworthy and more informative**: detect
disagreeing **dates** (today they are silently missed), and weight/annotate
conflicting values by **recency and a transparent authority hint** — while still
**surfacing every disagreement rather than auto-resolving it** (the v0.3/v0.4
conflict contract).

## 2. Decisions & scope

**In scope (always-on, deterministic):**
1. **Date-value fix.** `VALUE_RE` currently matches the bare-number alternative
   before the date alternative, so `31/12/2026` extracts as `31`. Two disagreeing
   dates therefore key to the same value and no conflict is flagged (a silent
   honesty gap codex found). Fix: order the **date** alternative *before* the
   bare-number alternative. (Amounts like `42,000,000` have no `/` so are
   unaffected; regression-tested against the full suite.)
2. **Recency + authority weighting, surfaced not resolved.** Each conflicting
   value is shown with its **source and date**, ordered newest-first (recency).
   A transparent, deterministic **authority hint** from the source path/filename
   (`executed|signed|final|amended|effective` → authoritative; `draft|wip|
   working|old|superseded|archive` → lower) is used as a same-date tiebreak and
   shown as a label. All values remain listed; docdex never picks a winner or
   hides a value; a footer reminds that newer/authoritative ≠ necessarily correct.

**Deferred (documented follow-ups, NOT this piece):**
- **Synonym-aware form-field conflict** (conflicts across synonym labels) — needs
  the deferred alias form-field value-extraction path (the one with the subtle
  date/false-conflict bugs). Its own careful sub-project.
- **ID-prefix mis-extraction** (`27AABC…` → `27`): a narrower `VALUE_RE` case;
  fixing it safely needs a letter-requirement on the ID pattern that interacts
  with pure-number amounts. Documented; not fixed here (lower impact than dates).
- **Optional recency-weighting of general evidence ranking** (a `--prefer-recent`
  tunable): interacts with the piece-3 reranker; a later tunable.

## 3. Design

**`VALUE_RE`** (context.py): move the date group
`(\b\d{1,2}[/\-]\d{1,2}[/\-]\d{2,4}\b)` to immediately after the currency group and
**before** the bare-number group. No other alternatives change. Group indices
shift, but every consumer uses `m.group(0)` (the whole match), so nothing depends
on group numbers — verify that assumption holds (grep for `.group(` on VALUE_RE
matches).

**`_authority(source: str) -> int`** (new): +N for authoritative filename
keywords, −1 for draft-ish; 0 if none. Deterministic, case-insensitive, path-wide.

**`_conflicts`** (context.py): unchanged grouping/normalization (equal amounts
still don't false-conflict). Change only the ordering of `reps`: sort by
`(recency, authority)` — recency primary (mtime desc), authority as the same-mtime
tiebreak — so behavior is identical when authority is absent (0 for all). Return
each rep so the caller can render source + date + authority label.

**Conflicts render** (context.py): replace the single terse line with, per
conflict:
```
- {label}: values disagree — verify (newer/authoritative ≠ necessarily correct)
  - {value} — {source} ({YYYY-MM-DD}){  · authoritative: signed}   ← newest/most authoritative first
  - {value} — {source} ({YYYY-MM-DD})
```
Dates come from `mtimes` (the inventory mtime already threaded in). If a source
has no date, omit the parenthetical. Keep it compact.

## 4. `--explain`

No new line required; the conflict section is self-describing. (Optional: note
`conflict ranking: recency + authority-hint` — include only if cheap.)

## 5. Testing plan (TDD)

- **Date conflict now detected:** two docs, `a` says a field is `31/12/2026`,
  `b` (newer) says `31/01/2027`; assert `## Conflicts` appears listing BOTH dates
  (fails before the `VALUE_RE` reorder — the revert check).
- **Amounts still fine:** `42,000,000` vs `40,000,000` still conflict; equal
  amounts written differently (`4.2 crore` / `₹4.20 cr`) still DON'T (no
  regression of DDX-032).
- **Recency order + dates shown:** the newer source is listed first and each line
  carries its date.
- **Authority hint:** with equal dates, a path containing `signed` is ordered
  above a `draft` path and labeled; all values still listed.
- **Surface-not-resolve:** every conflicting value still appears (none dropped).
- **No regression:** full suite green; update only conflict-format assertions in
  existing tests (never an honesty assertion), explaining each.

## 6. Risk & mitigation

| Risk | Mitigation |
|------|------------|
| `VALUE_RE` reorder changes other extractions | Only the date group moves; dates have `/` or `-`, amounts don't. Full-suite regression + report any changed extraction. |
| Conflict-format change breaks existing conflict tests | Expected; update format assertions (not honesty ones), documenting each. |
| Authority hint is a filename heuristic that could mislead | It's a labeled *hint* used only as a same-date tiebreak; every value is still shown; docdex never resolves. Footer states newer/authoritative ≠ truth. |
| Group-index shift in VALUE_RE breaks a consumer | All consumers use `group(0)`; verify by grep before relying on it. |
