# docdex v0.5.0 — Utility reranker (M1 / Phase 4, piece 3 of 5)

> Per-release design doc. Living plan is [`ROADMAP.md`](../ROADMAP.md). Covers
> only the reranker piece. Builds on stemming (piece 1) and aliases (piece 2).

_Date: 2026-07-22 · Branch: `feat/v0.5.0-reranker`_

---

## 1. Goal

Order retrieved evidence by **task utility**, not raw BM25 term-frequency, so the
chunk that actually carries a *labelled value* and *covers the query's words* ranks
above a chunk that merely repeats a query word. This is the **precision filter**
that offsets the extra recall stemming (piece 1) and synonyms (piece 2) introduced
— the standard hybrid-retrieval pattern (widen recall, then rerank for precision).

Success = the genuinely useful excerpt is packed first (and survives a tight
budget) more often, at the same token cost — without dropping honesty guarantees.

## 2. Decision

- **Built-in, deterministic, always-on** rerank of the evidence candidate pool.
  No dependency, no model, no randomness → same corpus + query → same order.
- The **pluggable external reranker** (`DOCDEX_RERANK_CMD`, off by default) named
  in the M1 notes is **out of scope for this piece** — the built-in utility rerank
  delivers the precision win with zero deps and keeps the default deterministic.
  Note it in the roadmap as a possible later, opt-in addition.
- Form-field ranking already uses a utility rerank (`_pick_field_hit`). This piece
  brings the same intuition to the **free-text / general evidence pool**, which is
  currently ordered by BM25 score alone.

## 3. Design

Today the evidence loop packs `sorted(pool, key=lambda c: -c["score"])` (BM25
only). Introduce a utility key and sort by it instead.

`_utility(cand, terms)` returns a tuple, compared high-to-low:
1. **value-bearing** (1/0): does the chunk contain a line that mentions a query
   term *and* a concrete value (`VALUE_RE`)? (Reuses `_value_lines`.)
2. **coverage**: number of distinct query terms (by stem) present in the chunk.
3. **label-value structure** (1/0): does it contain an explicit `Label: value`
   row for a query term? (A cheap regex signal that this is answer-bearing text,
   not prose that happens to repeat a word.)
4. **bm25 score**: the existing relevance, as the final tiebreak.

Evidence packing sorts by `_utility` (descending). Everything else is unchanged:
- The **existence** filter (`keep`) and the **relative floor** (`rel_floor`, a
  BM25 noise cut) are orthogonal and stay — reranking only reorders the
  floor-passing candidates; it never resurrects sub-floor noise nor drops a real
  hit except via the existing budget logic.
- **Source diversity** (`MAX_PER_SOURCE`) stays.
- Values remain literal; nothing is fabricated. Reranking changes ORDER only.

Determinism: stable sort with a fully-ordered key (bm25 tiebreak, then `rel` path
as a final deterministic tiebreak so equal-utility ties are reproducible).

## 4. `--explain`

Add one line: `- ranking: utility (value-bearing · coverage · label-value ·
bm25)`, so the ordering basis is visible and deterministic.

## 5. Testing plan (TDD, repro-first)

- A chunk carrying `Payment: ₹4.2 crore` for a "payment" query ranks ABOVE a
  higher-BM25 chunk that just repeats "payment payment payment" with no value.
- Coverage: a chunk covering two query terms outranks one covering one, at equal
  value-bearing.
- Source diversity preserved (`MAX_PER_SOURCE` still caps per source).
- Determinism: same inputs → identical evidence order across runs.
- No regression: full suite green; the form-filling benchmark
  (`test_task_benchmark.py`) holds or improves.
- Honesty unchanged: no new fabrication; a present fact still isn't dropped as
  missing; budget/coverage lines still accurate.

## 6. Out of scope

Pluggable `DOCDEX_RERANK_CMD` (optional, later), embeddings/RRF (piece 4),
conflict v2 (piece 5, which also absorbs the deferred synonym-aware form-field
extraction).

## 7. Risk & mitigation

| Risk | Mitigation |
|------|------------|
| Reranking shifts which evidence packs under tight budget → changed test expectations | Utility is a strict quality proxy; verify benchmark holds/improves; adjust only assertions that encoded the old BM25-only order, not honesty. |
| Non-determinism from unstable sort | Fully-ordered key incl. `rel` path tiebreak; stable `sorted`. |
| Over-favoring value-bearing lines hides prose context an agent needs | value-bearing is the FIRST key but coverage + bm25 still order within; MAX_PER_SOURCE keeps diversity; excerpts unchanged. |
