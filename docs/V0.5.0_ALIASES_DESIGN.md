## 1. Goal

Teach docdex that **different words mean the same thing**, so a task or form
field for **`legal name`** also finds a document that says **`Vendor`** or
**`Supplier`**. Stemming (piece 1) collided word *endings* (`governing`↔
`governed`); this handles true *synonyms* the corpus spells differently.

Success = higher field/recall coverage at the same token budget, **deterministic
and user-controlled**, and — the hard rule — **an alias never fabricates a
value**: it only widens which chunks are found and which labels are recognised;
the value shown is always the literal text from the document.

## 2. Decisions

1. **Curated, lean starter — user-owned, no *silent* built-in guesses.** `init`
   scaffolds `.docdex/aliases.json` pre-filled with a small set (~5–8) of
   high-stakes contract / due-diligence field-name mappings that the user reviews
   and trims. It is active because the user keeps it, every entry is visible and
   editable in that file, and nothing is baked invisibly into the tool. Keep it
   lean on purpose: aliases are the *exact, auditable guarantee* layer for the
   critical field names that must never miss; the optional **embeddings** piece
   (#4) covers the broad paraphrase long tail. An absent/emptied file → no
   aliases (pure stemming), so the user can always opt all the way out.
2. **Aliases MAY touch form field-value extraction** (unlike the deferred
   stem-field-extraction). This is safe here where it was not for stems: an alias
   is a *whole alternative word* that appears literally in the text (`Vendor`), so
   locating it and reading the value after it uses the real token's position — no
   mid-word landing. This is the flagship use (the roadmap's own example is a
   form field), so it is in scope.
3. **Honest provenance.** An alias-driven match is not a literal match of the
   user's term, so it is surfaced as approximate — reuse the stemming piece's
   `~approx` tag. `--explain` shows the alias expansions used.
4. **Deterministic.** No network, no model. Same corpus + same alias file → same
   result. Aliases compose with stemming (compare on stems, so `supplier`↔
   `suppliers` still align).

## 3. The alias file

`<project>/.docdex/aliases.json` — a JSON object mapping any term to its list of
synonyms; membership is **symmetric and transitive within a group** (if the file
says `legal name → [vendor, supplier]`, then a query for `vendor` also matches
`legal name` and `supplier`). `init` writes this **lean curated starter** (the
user trims/extends it):

```json
{
  "legal name": ["vendor", "supplier", "counterparty", "legal entity"],
  "governing law": ["jurisdiction", "governed by"],
  "effective date": ["commencement date", "start date"],
  "liability cap": ["limitation of liability", "maximum liability"],
  "termination": ["cancellation", "expiry"],
  "confidentiality": ["non-disclosure", "nda"]
}
```

Rationale for these six: they are the recurring, high-stakes field names in
due-diligence contracts where a rename genuinely happens, and each mapping is
high-confidence (low false-match risk). Deliberately excludes very common bare
words (e.g. `term`) whose broad aliasing would over-match — the user can add
those knowingly. Embeddings (piece #4) handle everything not listed.

- Keys and values are lowercased and split into stemmed tokens for matching.
- Multi-word aliases are supported (a group matches when all of a synonym's
  tokens are present, by stem).
- Absent file → no aliases (today's behaviour). Malformed file → treated as
  empty **with a one-line warning** (never crashes a sync/context).

## 4. New module: `aliases.py`

A small, dependency-free loader + expander:

```python

    # returns {} when the file is absent/empty/malformed (warns on malformed).

def expand_terms(terms: set[str], groups) -> set[str]: ...
    # union each term's alias group (by stem) into the term set, for RETRIEVAL
    # and existence checks only. Never used to extract or synthesise a value.
```

Leaf-ish module: imports `stem` from `docdex.stemming` (one-directional; no cycle
with `search`/`context`).

## 5. Where aliases apply — and where they must not

| Use | Aliased? |
|-----|----------|
| Query/field term expansion for retrieval | ✅ |
| `keep()` existence check (chunk matches a term OR its alias, by stem) | ✅ |
| Form field-label recognition (`_label_window` accepts alias tokens) | ✅ (position-safe: alias word is literal) |
| Free-text answer / evidence surfacing | ✅ |
| `~approx` provenance tagging | ✅ (alias match ⇒ approximate) |
| `--explain` alias display | ✅ |
| The extracted VALUE itself (`VALUE_RE` on raw text) | ❌ never |
| Conflict grouping keys | ❌ (unchanged this piece) |

Rule: aliases change **what is found and which label is recognised**, never the
literal value returned.

## 6. Integration points (verified against current code at plan time)

- `context._content_terms` / query build → expand via `expand_terms`.
- `context._candidates.keep` → existence uses expanded stem set.
- `context._label_window` / `_field_answer` → the field's label-token set is
  unioned with alias tokens; the value is still read from the window after the
  literal label token that is actually present.
- `context._approx_match` → a term matched only through an alias (its literal
  form absent) is approximate, same as a stem-only match.
- `context.build_packet --explain` → list alias expansions used.
- `scaffold.run_init` → write a commented `.docdex/aliases.json` example.
- Fallback `search.run_search` may stay alias-unaware this piece (aliases are a
  `context`-level concern; note it as a limitation) OR expand there too — decide
  at plan time based on code shape; prefer consistency if cheap.

## 7. Testing plan (TDD, repro-first)

- Loader: absent file → `{}`; well-formed file → symmetric/transitive groups;
  malformed JSON → `{}` + warning, no crash.
- `expand_terms`: `legal name` expands to include `vendor`/`supplier` stems.
- Context recall: with an alias file, `context "legal name"` surfaces a doc that
  only says `Vendor`; without the file, it does not (regression = default off).
- Form field: field `Legal name` pulls the value after a literal `Vendor:` label.
- Provenance: an alias-only match is tagged `~approx`; `--explain` shows the
  alias expansion.
- Honesty: the extracted value is byte-identical to the document; no alias path
  writes a value.
- No-alias default: full existing suite stays green.
